# Between Milestones 2 and 3: Standards and Quality Gate

**Goal:** One command checks everything (formatting, lint, types, tests), and the
project's rules are written down where both you and coding agents will read them.
No app behavior changes. Milestone 3 is the first milestone built under these rules.

**Done when:**

- `./check.sh` runs the format check, Ruff lint, mypy, and pytest with branch coverage,
  and exits non-zero if any of them fail.
- `./check.sh` passes on the current code.
- `AGENTS.md` at the repo root states the check command, the architecture rules, and
  the testing rules, in under ~40 lines. `CLAUDE.md` imports it, so Codex and Claude
  Code read the same rules.
- GitHub Actions runs `./check.sh` on every push and pull request.
- `docs/testing.md` holds the full testing standards (the table below).
- A coverage threshold is set from the measured baseline, not guessed.

## Decisions

| Question | Decision | Why |
| --- | --- | --- |
| Linter and formatter | **Ruff** for both | One fast tool replaces flake8, isort, and black. Works like ESLint and Prettier together. |
| Rule set | `E, F, I, B, UP, SIM, PT, RUF, PGH` | Catches bugs, import order, outdated syntax, and pytest misuse without the noise of `ALL`. |
| Line length / quotes | **88, double quotes**, Python 3.12 | Ruff's defaults; nothing to remember. |
| Type checker | **mypy, strict, on `src/` only** | SQLAlchemy 2.x and FastAPI are well typed. Tests stay informal. Pick one checker: don't also run pyright in CI. |
| Suppressions | Must name a code: `# noqa: B008`, `# type: ignore[arg-type]`, plus a short reason | `PGH` enforces the code part; the reason is a review rule. |
| Coverage | **Branch coverage**, threshold set after the baseline | Coverage is used to find gaps, not to show the code is ready. |
| CI | **GitHub Actions now**, running `./check.sh` after `uv sync --locked` | `origin` is already on GitHub, and one small workflow catches checks an agent skipped and keeps `uv.lock` honest. |
| Browser tests | **Deferred** until a feature depends on JavaScript | Playwright is heavy for a server-rendered app. |
| Agent instructions | **`AGENTS.md` holds the rules; `CLAUDE.md` is one line, `@AGENTS.md`** | Codex reads `AGENTS.md`, Claude Code reads `CLAUDE.md` and follows `@` imports. One source of truth, no symlink. Agents follow rules only if a file they load says so or a tool enforces them. |

## Tasks

Do them in order. Commit after each one so a noisy step is easy to back out.

### 1. Ruff

Add the dependency: `uv add --dev ruff`. Then configure it in `pyproject.toml`:

```toml
[tool.ruff]
line-length = 88
target-version = "py312"

[tool.ruff.lint]
select = ["E", "F", "I", "B", "UP", "SIM", "PT", "RUF", "PGH"]
```

Run `uv run ruff format .` and commit **only** the formatting changes, so later diffs
stay readable. Then run `uv run ruff check .` and fix the findings by hand. Use `--fix`
only for rules you understand (import sorting `I` and `UP` are safe).

If autogenerated Alembic files in `migrations/versions/` trip a rule, add a
`[tool.ruff.lint.per-file-ignores]` entry for that rule only, not an exclusion of the
whole directory.

### 2. Coverage

`uv add --dev pytest-cov`, then:

```toml
[tool.coverage.run]
source = ["tdee_calculator"]
branch = true

[tool.coverage.report]
show_missing = true
skip_covered = true
```

Run `uv run pytest --cov` and read the missing lines. Write down the baseline number
here. Don't set `fail_under` yet (task 5).

### 3. `check.sh`

Next to `run.sh`, in the same style:

```bash
#!/usr/bin/env bash
set -euo pipefail
cd "$(dirname "$0")"

uv run ruff format --check .
uv run ruff check .
uv run mypy          # added in task 4
uv run pytest --cov
```

`set -e` stops at the first failure. Leave out the mypy line until task 4.

### 4. mypy (strict)

`uv add --dev mypy`, then:

```toml
[tool.mypy]
python_version = "3.12"
strict = true
files = ["src"]
```

A trial run on the current code found 4 errors: 1 missing return annotation in
`app.py`, and 3 in `calc.py`. The `calc.py` ones come from lists filtered to days with a
weight but still typed `float | None`, because mypy can't carry a filter like
`if log.weight_kg is not None` into a later `log.weight_kg`.

Fix them by adding annotations, not with `Any` or `cast`. In `calc.py`, small refactors
that let mypy see the values aren't `None` are allowed, for example building a list of
`(date, weight)` pairs where the weight is a plain `float`, as long as behavior doesn't
change. The full `test_calc.py` suite must still pass unchanged; if a test has to change,
the refactor changed behavior. Each remaining `# type: ignore` needs a code and a
reason. Then add the mypy line to `check.sh`.

### 5. Coverage threshold

Look over what's not covered. Add tests where a gap is real behavior (a branch in
`db.py`, an error path in `config.py`). Ignore gaps that are just glue code. Then set
`fail_under` in `[tool.coverage.report]` to a whole number a little under the result,
so the next small change doesn't fail it for no reason.

### 6. `docs/testing.md`

The full standards, for when you're writing tests:

| Change | Required coverage |
| --- | --- |
| Calculations and unit conversions | Answers worked out independently, boundaries, missing data, invalid inputs; `pytest.approx` with an explicit tolerance |
| Database behavior | Real SQLite in `tmp_path`; check saved values, constraints, updates, and rollback where relevant |
| Routes and forms | `TestClient` through the real DB layer; check the response **and** what was saved |
| Migrations | Upgrade from empty, models and migrations agree (already in `test_db.py`), existing data survives schema changes |
| JavaScript behavior | Focused browser checks, once there is any |

Rules for every test:

- Test what the code does from the outside. Mock only outside boundaries (the browser
  opening, the clock if it's not passed in). Integration tests use the real database
  and app layers.
- Exception: when the order of steps *is* the behavior under test, a focused unit test
  can replace internal steps with recorders. Example: `test_main.py` checks that
  `prepare` (backup) runs before the server starts; migrations run in the app lifespan.
- Use fixed dates and isolated fixtures. Never touch the real `data/` directory, and
  don't depend on test order.
- A bug fix comes with a regression test that fails without the fix.
- Don't copy the implementation's formula into the assertion. Work out the expected
  value separately (see `test_calc.py`'s synthetic data).
- No snapshot tests.

### 7. `AGENTS.md` and `CLAUDE.md`

Write the rules in `AGENTS.md`. `CLAUDE.md` contains only the line `@AGENTS.md`, which
Claude Code expands. Put anything Claude-specific under that line, not in `AGENTS.md`.

Keep it short and specific. Agents follow brief rules better than long style guides.
Cover:

- **Commands:** `./run.sh` starts the app; `./check.sh` must pass before work is
  called done. Use `uv add`, never `pip install`.
- **Architecture:** `calc.py` is pure and imports only the standard library. Use
  kg/kcal internally; convert only at the edges. Read the clock only through
  `clock.py`. No raw SQLite-specific SQL outside `db.py`. Schema changes go through
  an Alembic migration.
- **Data:** never read or write the real `data/` directory.
- **Style:** type annotations on all `src/` code; suppressions name a code and a
  reason; match the surrounding code.
- **Tests:** link to `docs/testing.md`, plus the two rules agents break most often:
  don't copy the formula into the test, and don't mock internal layers (except to
  test the order of steps, as in `test_main.py`).
- **Plans:** milestones are in `docs/roadmap.md`, with details in `docs/plans/`.

### 8. CI

`.github/workflows/check.yml`, on `push` and `pull_request`:

```yaml
name: check
on: [push, pull_request]
jobs:
  check:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: astral-sh/setup-uv@v6
      - run: uv sync --locked
      - run: ./check.sh
```

`uv sync --locked` fails if `uv.lock` doesn't match `pyproject.toml`, so a dependency
added without updating the lock is caught. Make sure `check.sh` is executable in git
(`git update-index --chmod=+x check.sh` if needed). Check the action versions against
their READMEs when you write it.

## Milestone 3 requirements this sets up

The entry milestone must include real-database route tests for:

- creating an entry,
- saving an existing date (updates, doesn't duplicate),
- deleting an entry,
- rejecting an invalid submission **without changing what's saved**.
